==============================================================================
上下文关键信息保留率 A/B 实验
==============================================================================
设计:12 段 × 30 轮,每段在第 3~6 轮埋 5 个关键事实
      → 共 60 个事实槽位(分辨率 1.7%)
      上下文配置:摘要触发=30 条 · 滑窗=8 轮 · token 上限=3000
臂: A=摘要+滑窗(生产)  B=纯滑窗(基线)  C=全量历史(上限)

开始跑(12 轮摘要是真实 LLM 调用)...

------------------------------------------------------------------------------
结果:每个 arm 下 60 个事实槽位的保留情况
------------------------------------------------------------------------------
  臂                           指标1 上下文可寻址          指标2 答案命中
  A_摘要+滑窗         60/60 = 100.0%        60/60 = 100.0%
  B_纯滑窗           0/60 =   0.0%        0/60 =   0.0%
  C_全量历史          60/60 = 100.0%        60/60 = 100.0%

  按事实类型(指标2 答案命中率):
  事实                       A             B             C
  订单号           12/12 = 100%     0/12 = 0%  12/12 = 100%
  手机号           12/12 = 100%     0/12 = 0%  12/12 = 100%
  特别诉求          12/12 = 100%     0/12 = 0%  12/12 = 100%
  收货地址          12/12 = 100%     0/12 = 0%  12/12 = 100%
  快递偏好          12/12 = 100%     0/12 = 0%  12/12 = 100%

------------------------------------------------------------------------------
结论
------------------------------------------------------------------------------
  基线(纯滑窗)        = 0.0%
  现状(摘要+滑窗)     = 100.0%   相对基线 +100.0%(绝对) / +nan%(相对)
  上限(全量历史)      = 100.0%   现状距上限还差 +0.0%

  → 这就是「保留率」的可复现数字:摘要层把早期事实的可达率从 0% 提到 100%(+100% 绝对)。
