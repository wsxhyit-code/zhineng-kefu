- 保留订单选择、工单预览确认与取消、退款表单、知识引用、反馈以及历史会话交互。

## 使用方式

### 完整改造项目

解压 `zhineng-kefu-ui-updated.zip`，将原来的 `.env` 放到解压后的 `zhineng-kefu/` 根目录。沿用原项目的 Python 环境与 MySQL、Milvus、MCP 等服务，执行原有启动命令：

```bash
make dev
```

聊天工作台：`http://localhost:8000/`；管理首页：`http://localhost:8000/admin`。

### 只更新现有项目

将改造项目中的 `app/static/` 覆盖到现有项目同名目录。所有业务变更均限制在前端，该目录已包含完整的新页面、脚本、样式和图标。`scripts/ui-smoke.cjs` 为可选检查脚本，`docs/ui-redesign/` 为改造说明、预览和框架图。

刷新后若浏览器仍显示旧样式，使用 `Ctrl + F5` 强制刷新。

## 功能边界

- 订单和物流沿用原项目的确定性模拟数据。
- 退款操作创建退款工单，不直接执行支付退款。
- 人工转接沿用原项目的前端演示，并明确提示未接入真人坐席。
- 会话列表沿用当前浏览器对应用户的历史，并非多坐席接待队列。
- 历史接口目前返回对话文本；历史回看时不伪造以前的引用、工具记录与动作。本轮信息面板在下一次提问后刷新。
- 报表采用原接口返回的最近一次结果，不将离线报告标为实时业务指标。
- 主题分类器用于问题池旁路归类，不替换在线意图识别。

### 在线业务

1. 前端请求经 FastAPI 进入会话运行时，加载历史、摘要与滑窗；SQLite checkpointer 持久化图状态。
2. 指代消解后识别意图，商品咨询执行混合检索与重排，证据充分才进入主力 Agent，否则兜底并记录知识缺口。
3. 订单、物流与人工工单进入主力 Agent；退款与售后先校验或选择订单，再检索政策。
4. 主力 Agent 运行 ReAct 循环，通过统一引擎调用内置或 MCP 工具。建工单在工具节点中先中断确认，再续跑执行。
5. `submit_refund` 被转换为前端退款表单，用户提交后通过动作 API 登记退款工单。
6. 回复、来源、工具事件和操作卡片通过 SSE 展示；日志与回答按原逻辑持久化。

### 知识与运营

- 源文档与历史会话产生候选知识，审核后的知识通过双写流程写入 MySQL 原文与 Milvus 索引。
- 低置信度问题与负反馈落入问题池，经批处理标准化、查重进入审核队列；人工核准答案后写回知识库。
- 主题分类器旁路归类问题池，辅助判断优先补哪些知识。
- 工具审计、Langfuse、评估脚本与报告支持成本、质量趋势和阈值校准页面。
